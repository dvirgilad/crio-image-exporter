{{ if not .Values.storageInspection.enabled -}}
Exact per-image attribution is OFF. You are getting apparent image sizes, which
double-count layers shared between images. To learn how many bytes you actually
reclaim by deleting an image, enable:

  --set storageInspection.enabled=true

{{ end -}}
If pods log "permission denied" dialing the CRI socket, SELinux is blocking the
connection -- not file permissions. Confirm with:

  oc get pod -n {{ .Release.Namespace }} -l app.kubernetes.io/name={{ include "crio-image-exporter.name" . }} \
    -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.metadata.annotations.openshift\.io/scc}{"\n"}{end}'

That annotation must show the SCC this chart binds ({{ .Values.scc.name }}), and the
pod must be running with seLinuxOptions.type=spc_t. If the annotation names a
different SCC, the ServiceAccount is not getting the binding -- check:

  oc get rolebinding -n {{ .Release.Namespace }} {{ include "crio-image-exporter.fullname" . }}-scc

If your cluster enforces Pod Security Admission, the namespace also needs to
permit a custom SELinux type:

  oc label ns {{ .Release.Namespace }} pod-security.kubernetes.io/enforce=privileged --overwrite

Query example -- largest reclaimable images on each node:

  topk(10, crio_image_exclusive_size_bytes)
    * on(instance, image_id) group_right() crio_image_info
